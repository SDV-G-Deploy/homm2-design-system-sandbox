# V2 Site Kit - One-Hour Site Direction

This document reframes V2 for the next phase. V2 is not becoming a package yet.
It is becoming a practical site kit for quickly producing small pages in one
solar-civic fantasy interface.

## Goal

Build new small sites from known page templates, promoted helpers, and bounded
asset slots instead of redesigning each page from zero.

The working target is:

- one short brief;
- one selected template;
- one content pass;
- one asset-slot pass;
- smoke and visual verification;
- a publishable small site in about one focused hour.

This is an internal production target, not a public no-code promise.

## What The Kit Is

The kit is the current V2 repo-native workflow:

- `css/v2.css` as the shared CSS entrypoint;
- `v2/components.html` as promoted helper inventory;
- `starters/v2-site-starter/` as the copyable production seed;
- `starters/v2-site-starter/templates/` as page archetype templates;
- `docs/v2-asset-production-kit-2026-06-02.md` as the asset-slot rulebook;
- `sites/*` as production proofs.

## What It Is Not

Do not add these during the Site Kit phase:

- npm package;
- framework bindings;
- web components;
- build tooling;
- versioned release flow;
- generator from JSON or prompts.

Those only become useful after repeated consumer pain proves that copying the
starter is slower or more fragile than installing an external library.

## Template Set

The first target set is intentionally small:

| Template | Status | Use |
| --- | --- | --- |
| Product / landing page | First copyable template | Offer, course, product, campaign, small service |
| Report / proof page | Copyable template added | Case study, audit result, field note, evidence page |
| Dashboard / status board | Planned | Queue, readiness board, operational surface |
| Catalog / object list | Planned | Offers, objects, tools, routes, assets |
| Civic route / map-like page | Planned | Route, field kit, location/status narrative |

## Build Rule

For a new small site:

1. Pick one template before changing layout.
2. Replace product nouns, status rows, and CTA copy first.
3. Keep the topbar to 2-3 short product routes.
4. Use promoted helpers before creating page-local structures.
5. Fill bounded asset slots with existing V2 assets or page-local images.
6. Add page-local CSS only when the template cannot express the page.
7. Run smoke and visual capture before calling the site done.

## Asset Slots

Each template should name its visual slots explicitly:

- hero threshold image;
- route/status badge;
- inspection or water-lens visual;
- proof or result image;
- optional texture/background.

Every slot must have a stable size, alt text decision, mobile behavior, and a
fallback using existing `assets/v2/` material.

## First Template Verdict

The first template is `starters/v2-site-starter/templates/product-landing/`.
It is based on the existing starter and field-kit production proof, but turns
the page into a reusable offer structure rather than a single example.

Use it when the user needs a fast, recognizable, small product page in the V2
style. Do not treat it as proof that packaging is needed.

## First One-Hour Proof

The first fresh site built from this template is `sites/canal-signal-desk/`.
It keeps shared CSS unchanged and turns the template into a small launch-page
service site by replacing product nouns, route rows, fact cards, CTA copy, and
asset paths.

Early verdict: the template is useful for fast internal production. The main
remaining friction is still manual path adjustment and content judgment, not
package installation.

## Second Template Verdict

The second template is `starters/v2-site-starter/templates/report-proof/`.
It covers field notes, audits, case studies, and result pages where the job is
not to sell an offer but to explain what was inspected, what changed, and what
the reader should do next.

The first fresh site built from it is `sites/aqueduct-audit-note/`. It keeps
shared CSS unchanged and uses the report shape for a water-route audit note.
