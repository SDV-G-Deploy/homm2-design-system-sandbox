# V2 Slice 09 - Production Vocabulary And CSS Boundary

## Goal

Respond to the independent critic pass: V2 was judged useful but still too much like a laboratory unless production pages stop exposing system-building vocabulary and the CSS monolith gets an extraction boundary.

## Changes

- Cleaned customer-facing copy on production-like pages:
  - `v2/trial.html` now uses launch/signal/route language instead of proof/trial/primitive-board wording.
  - `v2/control.html` now reads as a live route desk instead of an operational page trial.
  - `v2/ant-school.html` replaces `Visible proof` / `HTML proof` with result-oriented copy.
- Added explicit section boundaries in `css/v2.css` so shared primitives, reference-only styles, and page recipes are easier to split safely.
- Added `docs/v2-css-boundary-2026-06-01.md` with the future file split map and production-copy rule.
- Updated README, starter kit, and acceptance boundary to make the vocabulary rule durable.

## Decision

Do not physically split `css/v2.css` yet. The class set is still settling after ANT School; a real split should happen after one more production recipe proves the shared components without new churn.

## Gate

Run after implementation:

- `git diff --check`
- `node tools/regression-smoke.js`
- visual capture for `v2/trial.html`, `v2/control.html`, and `v2/ant-school.html`

## Next

Build one more real product recipe with no sandbox vocabulary. If it reuses the same shell, ledger, command, route, and state classes cleanly, split the CSS into tokens / shell / components / reference / recipes.
